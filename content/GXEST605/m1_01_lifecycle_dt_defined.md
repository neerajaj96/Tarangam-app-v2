# Product Lifecycle & Design Thinking Defined

**From need to sunset — lifecycle stages, what design thinking is (and isn't), and innovation with intent.**

<a id="the-intuition"></a>
## 1. The Intuition

::: callout-intuition Core Mental Model: Human Life, Product Edition
Products are born (need spotted!), grow (designed/built/launched!), mature (optimized/scaled!), and retire (disposed/replaced — sunset planned, not stumbled into!). **Design thinking** is the parenting philosophy: human-centred, iterative laps (empathize→define→ideate→prototype→test!), divergent-then-convergent breathing per phase. It is *not* brainstorming-with-sticky-notes theatre (laps must *decide*: kill, pivot, or commit with evidence!).
:::

::: anim dt-loop Five Phases, Infinite Laps
Empathize feeds define feeds ideate feeds prototype feeds test — whose results re-enter empathize. Laps, not lines.
:::

## 2. Theoretical Framework & Formalism

### 2.1 Lifecycle stages + DT definition kit

* Lifecycle: need/opportunity → concept → design → build → launch → operate/scale → sunset (each gate: continue/pivot/kill with evidence!).
* DT definition: human-centred + iterative + collaborative + bias-to-action (prototype early!) + show-don't-tell.
* DT for product innovation (desirability∩feasibility∩viability Venn — IDEO's three lenses, all three or wobble!).

::: callout-formula KTU Formula Vault: Foundations
Lifecycle: **need→concept→design→build→launch→scale→sunset** · DT: **human-centred iterative laps** · innovation = **desirable∩feasible∩viable**.
:::

::: callout-pitfall Laps Without Gates Are Theatre
Iterating *without* kill/pivot/commit decisions (endless sticky-notes!) is process cosplay — each lap ends at a gate with evidence (user data! feasibility math!). Gate discipline (decide per lap!) separates method from theatre.
:::

## 3. Worked Example / Step-by-Step Scenario

::: step [Step 1: Setup] Formulating the Problem
"Campus mess-food-waste app idea: (a) place it on the lifecycle (with gate!), (b) run the three-lens check, (c) name the lap-zero activities."
:::

::: step [Step 2: Execution] Place, Lens, Lap-Zero
1. (a) Need/concept boundary (problem evidenced? mess audit numbers? — gate: quantified waste proof or kill!).
2. (b) Desirable (students/staff pain real?) · feasible (mess data + student devs?) · viable (who pays — mess contractor savings-share?) — wobble named per lens.
3. (c) Lap-zero: $5$ user chats + $1$-day waste weigh-in + stakeholder map (cook/students/management!) — evidence before pixels.
:::

::: step [Step 3: Conclusion] Final Result
Lifecycle placement, three-lens audit, evidence-first lap-zero. Gate-plus-lenses-plus-evidence is the foundations answer spine.
:::

## 4. Active Recall Quizzes

::: quiz Q1: Foundational Concept
Desirability–feasibility–viability Venn diagnoses:
(A) Team morale only
(*B) Which leg wobbles (loved-but-unbuildable? buildable-but-unpaid-for? profitable-but-unwanted?) — single-leg strengths fail as products (three-legged stool rule!)
(C) Colour schemes
(D) Meeting length
::: explanation
Leg-audit per idea (human want? technical can? business sustains?) — wobble named locates the next lap's work (desirability gaps → empathize!; feasibility → PoC!; viability → business-model!). Lens-routed next steps, not vibes.
:::

::: quiz Q2: Foundational Concept
Sunset planning belongs in lifecycle thinking because:
(A) Pessimism Looks thorough
(*B) End-of-life costs/impacts (e-waste! data migration! user offboarding!) designed *upfront* beat crisis handling (sustainability + trust + cost all favour planned exits!)
(C) Products never retire (they do — denial isn't strategy!)
(D) Auditors demand a slide
::: explanation
Exit-designed products (take-back! export tools! migration paths!) internalise end-costs early (design-for-disassembly discounts them!). Lifecycle completeness (birth-to-grave owned!) is the sustainability spine (M1.3 deepens!).
:::

::: quiz Q3: Foundational Concept
Iterative laps vs waterfall lines differ operationally by:
(A) Meeting count
(*B) Feedback timing + reversibility cost (laps: cheap early reversals via prototypes!; waterfall: late reversals expensive — big-bang integration risk!) — risk retires early in laps (fail cheap, learn fast!)
(C) Documentation volume
(D) Team size
::: explanation
Reversal-cost curves (cheap-early vs ruinous-late!) pick process shape (uncertain terrain ⇒ laps!). Risk-retirement schedule (what unknowns die which lap!) is the planning artefact — laps with a kill-list.
:::
