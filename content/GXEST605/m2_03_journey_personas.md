# Journey Maps & Personas

**Time-travel empathy — end-to-end experience cartography plus archetypes with a pulse.**

<a id="the-intuition"></a>
## 1. The Intuition

::: callout-intuition Core Mental Model: Travel Diary + Cast Bios
**Journey maps** diary the whole trip (stages → touchpoints → emotions-curve → pain/opportunity flags per stage! — backstage processes rowed beneath, frontstage feelings above!). **Personas** cast the leads (archetype bios: goals/frustrations/behaviours/quotes — *composites from research*, never invented mascots!). Diary shows *when* pain spikes (intervene there!); bios keep *whom* centred (design *for Rani*, not "users"!).
:::

<a id="the-math"></a>
## 2. Theoretical Framework & Formalism

### 2.1 Journey rows + persona anatomy + anti-patterns

* Journey: stages, touchpoints, user actions/thoughts/feelings (emotion curve!), pain points, opportunities, backstage processes (service blueprint pairing!).
* Personas: photo/name (respectful!), demographics-context, goals, frustrations, behaviours, quote, scenario uses (design decisions *tested* against personas: "would Rani...?").
* Anti-patterns: invented personas (fiction-as-foundation!), journey-happy-path-only (pain edited out!), persona-proliferation (dozens nobody remembers — $3\pm2$ working set!).

::: callout-formula KTU Formula Vault: Diary + Cast
Journey: **stages×touchpoints×emotions×pains×backstage** · personas: **researched composites, $3\pm2$**.
:::

::: callout-pitfall Happy-Path Journeys (Pain Edited Out!)
All-smiles maps (marketing decks, not diagnostics!) hide the redesign brief (pains *are* the opportunities!). Pain-hunting mandate (lowest-emotion stages circled first!) keeps journeys diagnostic.
:::

<a id="worked-example"></a>
## 3. Worked Example / Step-by-Step Scenario

::: step [Step 1: Setup] Formulating the Problem
"First-gen learner's admission journey (rural→college): (a) $5$-stage map with emotion curve + top pain? (b) One persona (research-composite!) with decision-test line? (c) Backstage row insight?"
:::

::: step [Step 2: Execution] Diary + Bio
1. (a) Awareness→inquiry→application→verification→enrolment; curve dips at *document verification* (multiple trips, opaque lists! — deepest pain circled, redesign target #1!).
2. (b) *Rani, 19, first-gen, Malayalam-medium, smartphone-shared*: goal (admission without city trips!), frustration (forms in alien English!), quote ("Will they laugh at my certificates?"), test-line ("Would Rani complete this step alone at night on shared data?").
3. (c) Backstage: verification officers batch-process weekly (frontstage pain = backstage batching! — redesign lever sits backstage, not in UI!).
:::

::: step [Step 3: Conclusion] Final Result
Curve-with-circled-pain, composite-persona with decision-test, backstage-lever insight. Pain-circled + lever-backstage + persona-tested is the journey-map completeness trio.
:::

## 4. Active Recall Quizzes

::: quiz Q1: Foundational Concept
Backstage rows (processes/systems) on journey maps matter because:
(A) Completeness aesthetics
(*B) Frontstage pains often root backstage (batch processes! siloed handoffs! policy clocks!) — redesign levers live behind the curtain (UI polish can't fix batch-weekly verification!)
(C) Stakeholders like swimlanes
(D) Tools default them
::: explanation
Pain-to-lever tracing (front symptom → back cause!) routes redesign spend (process vs pixels!). Backstage-blind maps prescribe UI for systems problems — layer-matched remedies only.
:::

::: quiz Q2: Foundational Concept
Persona decision-test ("Would Rani...?") works by:
(A) Roleplay fun
(*B) Concretising abstract users (named needs/behaviours judge features — faceless "users" accept everything, Rani vetoes!) — veto-powered design reviews (persona dissent recorded!)
(C) Marketing copy
(D) Demographic quotas
::: explanation
Specificity-as-test-harness (concrete constraints reject fluffy features!) — persona vetoes (documented dissent!) shape scope. Veto logs (what Rani killed!) evidence user-centredness.
:::

::: quiz Q3: Foundational Concept
$3\pm2$ persona working set (not dozens) since:
(A) Printing costs
(*B) Working-memory limits (team must *hold* personas live in decisions — dozens blur to "users" again!; priority archetypes only, revisited per phase!)
(C) Research budgets
(D) Template limits
::: explanation
Cognitive-carrying discipline (memorable few beat filed dozens!) — priority coverage (extremes + core in $3\pm2$!) with phase-revisits. Remembered-and-used beats archived-and-ignored.
:::
