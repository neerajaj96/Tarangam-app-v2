# Design Thinking Phases & Role of Empathy

**The five-phase map and why feeling-with beats thinking-about in design.**

<a id="the-intuition"></a>
## 1. The Intuition

::: callout-intuition Core Mental Model: Doctor's Rounds (Good Doctor!)
Empathize (bedside: symptoms *and* life context!), Define (diagnosis: sharp problem statement!), Ideate (treatment options brainstorm!), Prototype (low-dose trials!), Test (follow-up + adjust!). **Empathy's role**: patients misreport (say "fine" while wincing — observed-vs-stated gap!), workarounds reveal truths (pill organizers jury-rigged = adherence design brief!), emotions steer adherence (fear/confusion shape use!). Clipboards diagnose charts; empathy diagnoses humans.
:::

<a id="the-math"></a>
## 2. Theoretical Framework & Formalism

### 2.1 Phase contracts + empathy mandate

* Phases (contracts!): empathize (understand users/context!), define (actionable problem!), ideate (diverge/converge options!), prototype (tangible probes!), test (learn with users!) — laps allowed/expected!
* Empathy mandate (why-feeling-wins): latent needs (unasked-for insights!), stated-vs-observed gaps, emotional drivers, workaround gold (user hacks = R&D briefs!).

::: callout-formula KTU Formula Vault: Phases
Bedside → diagnosis → options → trials → follow-up · empathy finds **latent + emotional + workaround** truths.
:::

::: callout-pitfall Survey-Only Empathy (Checkbox Compassion!)
Surveys capture stated-averaged (blind to latent/emotional/workaround truths!) — observation + immersion required alongside (method mix mandated!). Single-method empathy claims fail audit — triangulate (ask *and* watch *and* live!).
:::

## 3. Worked Example / Step-by-Step Scenario

::: step [Step 1: Setup] Formulating the Problem
"Hostel laundry chaos brief: (a) phase-plan the fortnight? (b) Predict one stated-vs-observed gap + one workaround to hunt? (c) Triangulation mix?"
:::

::: step [Step 2: Execution] Rounds Scheduled
1. (a) Days $1$–$5$ empathize (laundry-room stakeouts!), $6$–$7$ define, $8$–$10$ ideate, $11$–$12$ prototype (token-board mock!), $13$–$14$ test (one wing pilot!).
2. (b) Stated ("machines broken!") vs observed (peak-hour queue physics + sock-loss dread!) — gap predicted; workaround hunt: bucket-hoarding + chalk-name-tags (system briefs hiding in hacks!).
3. (c) Interviews ($5$ Why-ready!) + shadowing (full wash cycles!) + diary/photo probes (laundry selfies with captions!) — triangulated.
:::

::: step [Step 3: Conclusion] Final Result
Phased calendar, predicted gaps/workarounds (hypotheses upfront!), triangulated methods. Hypothesis-led empathy (hunt list ready!) beats blank-slate wandering.
:::

## 4. Active Recall Quizzes

::: quiz Q1: Foundational Concept
Workaround-hunting (user hacks) outperforms feature-request lists because:
(A) Hacks are fun to catalog
(*B) Hacks reveal *felt* pains worth effort (revealed preference! — users already pay workaround-costs, proving value!) plus solution directions (hack mechanics suggest designs!) — requests state wishes, hacks prove wallets
(C) Requests are always wrong
(D) Hacks are easier to build
::: explanation
Costly-behaviour evidence (effort already spent hacking!) validates pain (willingness proven!) and hints shape (hack as prototype-zero!). Revealed-over-stated preference (behavioural economics cameo!) grounds discovery.
:::

::: quiz Q2: Foundational Concept
Stated-vs-observed gaps arise (and matter) since:
(A) Users lie maliciously
(*B) Recall limits + social desirability + tacit knowledge (can't articulate habits!) — observed behaviour corrects (triangulation!), designs fit reality not reports
(C) Surveys are useless (useful *with* observation — mixed methods!)
(D) Designers distrust everyone
::: explanation
Articulation limits (tacit routines!) + reporting biases (pleasing answers!) guarantee gaps — observation corrects (watch the doing!). Gap-hunting as method (predict gaps, then check!) structures empathy work.
:::

::: quiz Q3: Foundational Concept
Phase-skipping (straight to prototype!) forfeits:
(A) Nothing if the idea is good (ideas unvalidated are bets, not knowledge!)
(*B) Problem-validity (solving non-problems expensively!) + user-fit (unexamined needs!) — prototype-first gambles build-speed against relevance-roulette (occasionally wins, usually burns!)
(C) Team morale always
(D) Documentation volume
::: explanation
Relevance risk (right-thing question!) precedes execution risk (right-way question!) — phases sequence risk-retirement (validate problem, then solution!). Skipping gambles the expensive half (building!) to save the cheap half (asking!).
:::
