# Define: Storytelling, Critical Items & Success

**From mess to mission — narrating findings, diagramming what matters, and writing success before solutions.**

<a id="the-intuition"></a>
## 1. The Intuition

::: callout-intuition Core Mental Model: Doctor's Diagnosis Speech
**Storytelling** presents findings as narrative (protagonist-Rani, struggle, stakes — *felt* truth that moves stakeholders, not bullet-point autopsies!). **Critical-items diagrams** map what *must* hold (must-haves vs delights vs don't-cares — Kano-flavoured triage!). **Define success** writes finish lines *before* racing (metrics + thresholds + non-goals! — "reduce verification trips from $3$ to $1$" beats "improve experience" vapor!). Diagnosis speech: story (feel it!), items (scope it!), success (measure it!).
:::

---

<a id="the-math"></a>
## 2. Theoretical Framework & Formalism

### 2.1 Story spine + items triage + success spec + POV statements

* Story: character→struggle→stakes→insight (evidence-anchored beats!).
* Critical items (must/delight/ignore triage per finding!).
* Success: metric + threshold + timeframe + non-goals (anti-scope-creep!).
* POV format ("[User] needs [need] because [insight]" — M2.2 insight sentences graduate here!).

::: callout-formula KTU Formula Vault: Define Trio
Story (**feel it**) · items (**scope it**) · success (**measure it**) · POV (**user-needs-because**).
:::

::: callout-pitfall Solution-Masked-as-Problem ("Need an app!")
Define-phase smuggling (prescribed solution parading as need!) strangles ideation (one answer pre-chosen!). Need-language policing (verbs of human lack, never product nouns!) keeps problem space open.
:::

---

<a id="worked-example"></a>
## 3. Worked Example / Step-by-Step Scenario

::: step [Step 1: Setup] Formulating the Problem
"Canteen brief (M2.1–2.3 continued!): (a) $4$-beat finding story? (b) Critical-items triage ($6$ items!)? (c) Success spec + POV? (d) Solution-masking audit?"
:::

::: step [Step 2: Execution] Speech Delivered
1. (a) Rani skips lunch twice weekly (stakes: health/grades!) → queues *are* timetable physics + token chaos (struggle!) → insight: *predictability*, not speed, is the hunger (turn!).
2. (b) Must: live queue visibility + token fairness! Delight: pre-order favourites! Ignore: loyalty points (scope-cut, stated!).
3. (c) Success: median wait-display accuracy $\pm2$ min + skipped-meal rate halved in $6$ weeks; non-goal: kitchen throughput rebuild!
4. (d) "Need an app" → reworded: "need *meal-certainty* before the $1$pm class" (need preserved, solution reopened — app *may* still win, unprescribed!).
:::

::: step [Step 3: Conclusion] Final Result
Story-beats, triaged items, measured success, de-prescribed needs. POV-plus-metrics (mission + finish line!) hands ideation a *brief*, not a blur.
:::

<a id="self-check"></a>
## 4. Active Recall Quizzes

::: quiz Q1: Foundational Concept
POV "[User] needs [need] because [insight]" disciplines by:
(A) Fill-in-the-blank fun
(*B) Forcing *human-need* (not solution!) + *evidenced* rationale (insight from research!) into one testable sentence (brief quality checkable pre-ideation!)
(C) Longer documents
(D) Stakeholder flattery
::: explanation
Sentence-as-contract (need + evidence, no solution nouns!) — POV review gates ideation entry (blurry POVs bounce back!). Contract quality (testable, human, evidenced!) judges readiness.
:::

::: quiz Q2: Foundational Concept
Success metrics *before* ideation (not after) since:
(A) Bureaucratic order
(*B) Metrics steer search (optimise *toward* finish lines!) and gate keepers (kill ideas missing thresholds *early*!) — post-hoc metrics rationalise whatever emerged (motivated measuring!)
(C) Teams idle otherwise
(D) Funders demand Gantt filler
::: explanation
Search-steering + early-kill functions (metrics as compass *and* gate!) require pre-commitment (define-then-diverge sequence!). Post-hoc metricshopping (fit measures to favourites!) is the failure mode named.
:::

::: quiz Q3: Foundational Concept
Non-goals in success specs prevent:
(A) Ambition generally
(*B) Scope-creep drift (explicit out-of-bounds! — "not rebuilding kitchen throughput" protects the queue-visibility mission from expansion entropy!) — boundary honesty (named limits!) preserves focus
(C) Hard work
(D) Stakeholder input
::: explanation
Named-exclusions (scope edges drawn!) defend missions (every yes invites scope cousins!). Boundary-first scoping (outs listed with ins!) is the focus discipline — say no early, build yes deeply.
:::
