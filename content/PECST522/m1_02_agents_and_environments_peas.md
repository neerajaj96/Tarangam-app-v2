# Agents and Environments: The PEAS Framework

**Sensors, actuators, percept sequences, agent functions vs. agent programs, and PEAS specification.**

<a id="the-intuition"></a>
## 1. What is an Agent?

In Artificial Intelligence, the word "agent" describes the actual computational entity that perceives, reasons, and executes actions.

**Definition:** An **Agent** is anything that can perceive its environment through **sensors** and act upon that environment through **actuators**.

::: callout-intuition Core Mental Model: You Are an Agent!
Think about yourself crossing a busy street:
* Your **Sensors** are your eyes and ears (taking in data about speeding cars).
* Your **Environment** is the physical road, the weather, and the traffic.
* Your **Actuators** are your legs (moving you across the street) and your vocal cords (yelling at a bad driver). 
* Your **Agent Program** is your brain, instantly deciding whether to run or stop based on what your eyes see.

In software, a web-scraping bot is an agent. Its sensors receive raw HTML text, its environment is the Internet, and its actuators dispatch HTTP requests to fetch pages and click links.
:::

<a id="terminology"></a>
## 2. Key Terminology for Beginners

Before designing an AI system, we must establish the formal language of agent architectures:

* **Percept:** A single snapshot of raw sensory data that the agent's sensors capture at a specific instant in time (e.g., a camera frame detecting a red light right *now*).
* **Percept Sequence:** The complete chronological history of everything the agent has ever perceived since its initialization. Rational agents often base their decisions on the entire sequence rather than just the isolated current percept.
* **Action:** The discrete or continuous output physical/digital command generated by the agent's actuators (e.g., applying 15% brake pressure).

### Agent Function vs. Agent Program

This is a classic university exam distinction:

::: callout-formula The Agent Function
Mathematically, an agent's behavior is formalized by the **Agent Function**, an abstract mapping from any given percept sequence to a specific action:
$$f: P^* \rightarrow A$$
Where:
* $P^*$ is the set of all possible percept sequences (the entire history of inputs).
* $A$ is the set of all possible actions.
* $f$ is the abstract mathematical rule connecting them.
:::

* **The Agent Function** is an *abstract, mathematical concept*. It represents a hypothetical infinite lookup table that dictates: "For any historical percept sequence $p \in P^*$, execute action $a \in A$."
* **The Agent Program** is the *concrete, physical software implementation* (written in Python, C++, etc.) running on a physical computing platform (CPU/GPU) that calculates and executes the Agent Function in real time.

<a id="the-dimensions"></a>
## 3. The PEAS Framework Explained

When engineers specify an AI system, the very first task—before writing code or picking neural architectures—is to rigorously define the **Task Environment** using the **PEAS** framework:

* **[P] Performance Measure:** The external, objective criteria used to evaluate the success and quality of the agent's behavior. It answers: *"What makes this AI successful?"*
* **[E] Environment:** The external context, world, or simulator in which the agent operates. It includes everything the agent interacts with but does not directly control.
* **[A] Actuators:** The physical mechanisms, motors, or digital interfaces through which the agent acts upon and alters the environment.
* **[S] Sensors:** The physical or digital sensing devices the agent uses to read data from the environment.

::: callout-pitfall Performance Measure vs. Internal Utility
Never confuse the **Performance Measure** (which is assigned externally by the system designer/evaluator) with the agent's internal calculation.
For a chess bot, the Performance Measure is simply "Winning the match according to official rules." We evaluate the *external outcome in the environment*, not how high the agent's internal evaluation heuristic scored during search.
:::

## 5. Designing the Performance Measure: Avoiding Unintended Behavior

Designing an objective Performance Measure is critical. A rational agent will ruthlessly maximize the exact mathematical function it is given, often exploiting edge cases in unexpected ways.

::: callout-intuition The Vacuum Cleaner Paradox
Suppose you design a robotic vacuum cleaner and define its Performance Measure as: **"Total amount of dirt sucked up into the dustbin."**

What does an optimal rational agent do?
It cleans the dirt, **dumps the dustbin back onto the clean floor**, and vacuums it up again in an infinite loop! It achieves a near-infinite score on your metric, yet leaves the room perpetually dirty.

**The Fix:** Performance measures should evaluate the *desired state of the environment*, not the agent's internal actions. The proper metric is: **"Award +1 reward point for every clean square per unit of time."**
:::

::: quiz Why is it dangerous to set a self-driving car's performance measure strictly to "Minimize total trip duration to the destination"?
() The car will fail to initialize its GPS sensors.
(*) The car might speed excessively, ignore traffic lights, and endanger pedestrians to shave off seconds.
() The car will drive in infinite circles to gather percepts.
() The car will run out of battery before planning a route.
::: explanation
If you reward only minimum time and omit safety or legal penalties, the agent treats speed as the sole objective, disregarding safety and road regulations.
:::

### Sample 3-Mark Question
**Q: Define the PEAS framework used in designing intelligent agents.**

**Model Answer:**
The PEAS framework formalizes an agent's task environment before implementation:
* **[P] Performance Measure:** The metric used to quantify the success of the agent's behavior (e.g., safety, fuel efficiency, accuracy).
* **[E] Environment:** The external domain the agent interacts with (e.g., roads, hospital databases, chess board).
* **[A] Actuators:** The output mechanisms the agent uses to effect changes (e.g., steering motors, screen displays).
* **[S] Sensors:** The input devices used to perceive environmental state (e.g., cameras, microphones, keyboards).

### Sample 7-Mark Question
**Q: Explain the difference between an Agent Function and an Agent Program. Formulate the complete PEAS description for an Automated Taxi Driver.**

**Model Answer:**
**Part 1: Agent Function vs. Agent Program (3 Marks)**
* **Agent Function:** An abstract mathematical mapping ($f: P^* \rightarrow A$) from any percept sequence $P^*$ to an action $A$. It specifies the theoretical ideal behavior.
* **Agent Program:** The concrete software implementation executing on a physical computing architecture (hardware) that computes and realizes the agent function in real time.

**Part 2: PEAS Specification for Automated Taxi Driver (4 Marks)**

| PEAS Component | Automated Taxi Driver Specification |
| :--- | :--- |
| **Performance Measure** | Safety, speed, adherence to traffic laws, passenger comfort, fuel efficiency, profit maximization. |
| **Environment** | Urban streets, highways, traffic, pedestrians, cyclists, changing weather, road construction zones. |
| **Actuators** | Steering mechanism, accelerator throttle, hydraulic brakes, turn signals, horn, display dashboard. |
| **Sensors** | Cameras, LiDAR, radar, ultrasonic sonar, GPS receiver, speedometer, accelerometer, engine diagnostic sensors. |
